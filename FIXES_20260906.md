# Audio loader v6.1

## Startup crash and rollback — 2026-09-06

The user reported an immediate crash with v6. The installed proxy, optional
loader DLL and registry were restored from `AudioBackups/20260906_005307`, with
matching SHA-256 hashes. The user subsequently confirmed the restored version
launches normally. v6.1 is built in `dll/release/`; the latest deployment receipt
in `staging/DEPLOYED_SHA256.json` identifies the files installed by the deploy tool.

The 13:19:52 dump (`e340b04066eded937723d5aa5303681b.dmp`) records an access
violation in the failed proxy at RVA `0x32F7`, in the stack-probing loop. Its caller
at RVA `0x1890` requests `0x10030` bytes of stack. The file hooks allocated
32,768-wide-character local path arrays; the original native harness used the
main thread's larger stack and did not call the real hooks on a small game stack.

v6.1 removes those hook-local arrays, compares path characters without a copy,
stores the redirect target once in static storage, moves the log-path buffer to
the heap, and reserves a separate 1 MiB stack for the loader's worker thread.

`hook_stack_test.c` now calls the real hook functions on a 64 KiB fiber stack.
Compiled against the preserved failing source it exits with `0xC00000FD`
(stack overflow). The fixed source passes 200 hook calls and error-code checks.
All 24 regression tests pass. This fixes the reproduced stack defect. The game
now launches on v6.1 and creature-driven playback was confirmed by ear in game
(UltimasaurusCE, rebuilt banks); neither is covered by the automated tests, so
re-check both after any loader or game update.

The shared component still owns one merged registry. Species mods ship their
own `.bnk` pair and `.wmetasb.add` fragment. No stock game files are replaced.

## Installation and updates

The production files are `dll/release/xinput1_4.dll` (game root), the optional
`dll/release/VLAudioLoader.dll` (`Win64/ovldata/VLAudioLoader/`), and the merger's
`audiometadata.ovl` plus `audio_manifest.sha256` (`VLAudioLoader/Audio/`). Install
with the game closed. Run the merger after adding/removing/changing audio mods
or after a game update changes stock metadata. An invalid/missing manifest now
disables custom bank loading and uses the stock registry, with a log explanation.

The merge launcher accepts `--game PATH` and `--cobra PATH`. It can detect Steam
libraries and the game containing the scripts. Cobra lookup supports
`JWE3_COBRA_TOOLS` or an adjacent `audio_tools.json` containing
`{"cobra_tools": "D:/path/to/cobra-tools-master"}`. A configured invalid directory
is an error, never a silent fallback to a different tool version.

**Cobra is NOT bundled.** cobra-tools is **GPLv3**; shipping a copy would put
this kit under those terms, including the obligation to make corresponding
source available. So the kit requires your own checkout and never redistributes
one. `vendor/` is gitignored: keep a local copy there if you like, it just is
not published.

Point the kit at your checkout with `python audio_kit_gui.py` (saved to
`audio_tools.json`), or per-command with `--cobra`, or via `JWE3_COBRA_TOOLS`.
A configured invalid directory is an error rather than a silent fallback.
Never ship `audio_tools.json` with a mod - it holds your machine's paths.

`deploy_local.py` (maintainer tool) installs the kit self-contained: the scripts,
docs and `requirements.txt` travel together, so the
installed copy needs no checkout of its own. It no longer writes an
`audio_tools.json`. Two flags:

* `--tools-only` updates scripts and docs while leaving the loader
  DLLs and the merged registry untouched, and needs no staged manifest.
  Without it an existing override is preserved, because a user may have pointed
  it at another checkout deliberately. Note that an override left in place keeps
  taking precedence — including one naming the stale
  `Main Mod Kit\cobra-tools-master`, which is the copy that corrupts JWE3
  dinosaur OVLs.

Deployment backs up first, verifies every written file by hash, and rolls back on
failure — restoring the receipt and the removed config too, attempting every
restore even if one is locked, and retaining the backup when rollback is
incomplete.

`merge_audio_registry.py --check` validates inputs without modifying game files.
`--output DIR` builds a verified staging artifact instead of deploying. `--work`
selects an existing parent for private temporary scratch, not a folder to clear.
Set `VLAUDIO_NO_PAUSE=1` for unattended BAT execution.

## Fixes

- Rebuilds stock-only metadata when the last fragment is removed.
- Parses XML, rejects conflicting mod declarations/bank content and missing banks;
  byte-identical duplicates are deduplicated. Preserves vanilla's repeated bank rows.
- Compares all registry records after extraction, not just bank counts.
- Checks Cobra exit status and captures stderr; supports both observed CLI log styles.
- Uses atomic file replacement. A manifest committed last detects interrupted deployments.
- SHA-256 manifest covers stock registry, merged registry, fragments and bank files;
  added/removed files and preserved timestamps cannot masquerade as a fresh merge.
- Native loader uses executable-relative Unicode paths, dynamic bank inventory,
  successful audio opens on both CreateFile APIs, Wwise IsInitialized, and bounded
  retries for startup dependencies. Media banks load before event banks.
- Bank buffers are freed after the synchronous copy call and on every failure.
  Banks are hash-checked again immediately before loading.
- XInput initialization is synchronized. Hook wrappers preserve file API error codes
  and chain the currently installed imports. A missing import name table is skipped safely.
- Only the shared stock metadata path is redirected. Arbitrary basename-based OVL
  replacement was research functionality, is not part of the v6 raw-bank mod contract,
  and is no longer allowed to override another mod's registry.
- Legacy v4/v5 source/build names use one production implementation. The standalone
  Lua entry point defers to an installed root proxy, preventing duplicate scans.
  `fnVLDiag` logs guidance rather than posting diagnostic sounds into the game.
- Custom WEM replacement uses the already-renamed event/media IDs consistently,
  rejects unmatched or conflicting replacements, and keeps media size corrections.
- Remapping protects the complete type/size header from overlapping writes;
  malformed chunk/HIRC/DIDX extents are rejected and named ID collisions fail early.

## Validation and limits

Run `python -m unittest discover -s . -p "test*.py"` from the kit folder;
build native fixtures first with `dll/build.bat`.
The native executable uses a fake Wwise callback and never runs the game API.
The release builds with MSVC x64 `/W4 /WX /MT` (warnings are errors).

The packaging follow-up passes 34 tests (24 audio, 10 packaging). It covers
configuration preservation, explicit migration, receipt failure rollback,
continued restoration after a locked file, tools-only runtime preservation,
and corrupt or missing files. A missing entry point now fails
integrity verification instead of silently selecting a sibling checkout.
Real merges using a configured `cobra-tools-master` checkout
round-tripped 620 bank records and produced identical registry and manifest
bytes for the current two-mod installation. This comparison covers the audio
registry, not other OVL formats.

Offline tests cover merge/uninstall/collision/failed-write cases, custom WEM IDs,
manifest changes with preserved timestamps, Unicode paths, 70 banks, and duplicate
load suppression. A real two-mod registry build round-tripped all 620 bank records.
The remapper produced identical bank bytes to the previous algorithm for the two
sampled vanilla donor banks, and the seven-file Cobra corpus check had no drift.

These are tool/vanilla checks, not an in-game playback certification for v6.1.
After deployment, launch normally, load a park containing both custom species,
and verify creature-driven roars plus normal stock audio. Check VLAudioLoader.log
for v6.1, manifest verification, and four successful unique
bank loads. Startup still relies on the worker installing imports before the
game's first metadata open; this should be checked on a real launch.

The byte-scanning HIRC reference remapper remains a format heuristic, even with
the header fix. A fully typed Wwise remapper is separate format-research work.

## Correction 2026-09-06: a byte-identical `.wmetasb.add` does NOT mean "no merge"

Swapping a species' sound payload while keeping its prefix produces an identical
registry fragment, which looks like the merge can be skipped. It cannot.

Loader v6.1 also keeps `audio_manifest.sha256`, which hashes the installed
**`.bnk` files**. Replacing a bank invalidates the manifest, and the loader's
response is all-or-nothing: it disables **every** custom bank - including other
mods' - and falls back to the stock registry. The symptom is total silence rather
than a wrong sound, which is why it gets misread as a broken build.

Seen on UltimasaurusCE after a payload swap:

```
Audio content changed/missing: ChaosEffectUltimsaurus/Audio/ultimasaurusce_events.bnk
Audio manifest mismatch: install/remove/update detected. Run merge_registry.bat
Custom banks disabled until a valid registry merge is installed.
```

Re-running the merge restored `Audio manifest verified (8 files, SHA-256)` and all
8 manifest entries matched. **Rule: touch a `.bnk`, run the merge.**
